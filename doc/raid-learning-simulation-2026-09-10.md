# Raid Learning Cards — simulation และ release

วันที่ 10 กันยายน 2026

## เกณฑ์ที่ยึด

GDD v1.0 §4.12 กำหนด stat รวม 45/60/75% (ผลรวม 5 ค่า ÷ 500) และคำตอบถูกอย่างน้อย 60% ต้องผ่านทั้งสองด้านเพื่อชนะ การลด HP บอสหมดอย่างเดียวไม่เพียงพอ หน้าจัดชุดและสนามแจ้งเงื่อนไขนี้ก่อนเล่น

## ข้อมูลและวิธีจำลอง

อ่านข้อมูลจากฐานข้อมูลจริงแบบไม่แก้ข้อมูล: มอน Stage 4 ที่เก็บเข้าสมุด 128 ตัว ใช้ได้ 125 ตัว อีก 3 ตัวไม่มี snapshot จึงแยกออก ไม่แทนค่าว่างด้วยมอนอ่อนเพื่อบิดผล ข้อมูลทดสอบเก็บเฉพาะ stat และชนิดไข่ ไม่มีชื่อ user ID หรือข้อมูลติดต่อ

จำลองชุดเดิมไม่ใส่ของ และชุดสมมุติที่ถูกกติกา q1/q3/q4: หัว ATK/HP, ตัว DEF/ATK, เท้า SPD/DEF ไม่ซ้ำ main stat ไม่เพิ่ม FOC และจำกัดตาม cap ของไข่จริง ชุดสมมุติไม่ใช่การอ้างว่าผู้เล่นมีของเหล่านี้อยู่แล้ว

ใช้ policy รับมือเดียวกันทุกชุด โดยอ่านเฉพาะท่าที่บอสประกาศ/มือการ์ด/พลัง/เลือด ไม่รู้ผลสุ่มข้างหน้า ทดสอบโอกาสตอบถูก 40/60/80/100% แยก RNG คำตอบกับ RNG ต่อสู้ ใช้ 30 seeds ต่อเงื่อนไข

รอบแรก 180,000 การต่อสู้ → จูนครั้งแรก 60,000 → ยืนยันรุ่นสุดท้าย 180,000 รวม 420,000 รอบ

## ผลรุ่นสุดท้าย

กลุ่มไม่ใส่ของ stat อยู่ตั้งแต่เกณฑ์ถึงไม่เกิน 5 จุดเปอร์เซ็นต์เหนือเกณฑ์:

| ด่าน | จำนวนมอน | ตอบถูกเฉลี่ย 60% | 80% | 100% | เทิร์นเฉลี่ยเมื่อ 100% |
|---|---:|---:|---:|---:|---:|
| ridge_mist | 9 | 25.2% | 61.9% | 87% | 11.9 |
| ridge_gale | 8 | 19.6% | 56.7% | 81.3% | 13.9 |
| ridge_storm | 9 | 30% | 80.4% | 98.9% | 10.5 |

เปอร์เซ็นต์ตอบถูกเป็นโอกาสสร้างคำตอบแต่ละข้อใน simulation อัตราจริงต่อรอบย่อมแกว่ง การชนะทุกครั้งยังถูกตรวจว่าคำตอบถูกในรอบนั้นอย่างน้อย 60% มอนต่ำกว่าเกณฑ์ stat ไม่มีรอบชนะ

นี่คือผลจาก policy และกลุ่มมอนที่มีอยู่ ไม่ใช่ผลเล่นของเด็กจริงหรือการรับประกันทุก build การผ่านขั้นต่ำเปิดโอกาสชนะ ไม่ได้ทำให้ทุกแผนชนะอัตโนมัติ

## จุดที่ปรับ

- บอส HP 200/270/430, พลังโจมตี 16/22/34, เกราะ 6/10/14 และ DC เริ่มต้น 45/60/75
- แทงจุดอ่อนคำนวณดาเมจจาก FOC ให้มอนสายความแม่นยำมีทางทำดาเมจจริง
- ตอบผิดลดดาเมจเหลือ 40% ของผลพื้นฐาน ฟื้นเลือดครึ่งหนึ่ง การป้องกันครึ่งหนึ่ง และไม่เกิดผลพิเศษ
- ทุกคำสั่งรวมโจมตี/ตั้งหลักต้องเลือกการ์ด → ตอบ → เฉลย → ไปต่อ เลือกแล้วล็อกโจทย์ ไม่เปลี่ยนเทิร์นจนส่งคำตอบ
- คำถาม active ตาม grade_band ของผู้เล่น: junior คละ math/science; senior คละ branch (physics/chemistry/biology) สุ่มจากวิชาที่ใช้ไปน้อยที่สุด แล้วบทที่ใช้ไปน้อยที่สุดในวิชานั้น แล้วสุ่มข้อใหม่ในรอบ ไม่ให้น้ำหนักประวัติตอบผิด ไม่ส่ง correct_index/explanation ก่อนตอบ
- quiz_attempts ใช้ source=raid_boss แบบเดิม ไม่มี EXP ไม่เปลี่ยนสูตรเลี้ยง/วิวัฒนาการ/อุปกรณ์ PvP

## การปล่อย

Apply migrations 20260910044249_raid_card_battles_v2.sql และ 20260910044259_raid_card_learning.sql ก่อนโค้ด main รุ่นใหม่ โหมดใหม่เปิดเป็นค่าเริ่มต้น ปิดกลับ legacy สำหรับรอบใหม่ด้วย RAID_CARD_BATTLES_ENABLED=false รอบที่ค้างยังเล่นต่อได้

ทดสอบ npm run test:raid (รวม SQL จริงบน PGlite), TypeScript/lint/build และ browser มือถือ/desktop ตรวจโจทย์ค้างหลัง reload ตอบถูก/ผิด ชนะ/แพ้ ไม่ซ้ำเทิร์น/รางวัล ก่อน push main

รันจำลองซ้ำ: node --experimental-strip-types tests/raid-cards/simulate.ts ผลละเอียดอยู่ .cache/raid-simulation.json; กำหนด RAID_SIM_SEEDS เพื่อลด/เพิ่มรอบได้

ฐานข้อมูล production apply แล้วและตรวจ RLS/สิทธิ์แล้ว ผู้เล่นอ่านเฉลยก่อนตอบหรือเรียกตัวบันทึกผลโดยตรงไม่ได้ เลข migration ใน repo ตรงกับ registry จริง

## แก้การสุ่มค้างบทเดิม (10 ก.ย. 2026)

กฎเดิมเรียงบทที่ตอบผิดล่าสุดหรือบทอ่อนก่อนทุกครั้ง ทำให้สุ่มได้บทเดิมจนกว่าจะใช้ข้อในบทหมด เปลี่ยนเป็นคละวิชาและบทภายในช่วงชั้น โดยวิชา/บทที่เหลือข้อให้สุ่มมีโอกาสกระจายใกล้เคียงกันแม้ขนาดคลังต่างกันมาก หากกลุ่มใดหมดให้เลือกกลุ่มที่ยังมีข้อได้ โจทย์ที่ล็อกไว้ก่อนอัปเดตยังเป็นข้อเดิมจนตอบเสร็จ

`tests/raid-cards/question-mix.test.ts` รันฟังก์ชัน SQL จริงบน PGlite: 20 ข้อต่อช่วงชั้น junior 10/10 และ senior 7/7/6 เมื่อทุกวิชามีข้อเพียงพอ ครบทุกบทใน fixture, ไม่ข้ามช่วงชั้น, ไม่ซ้ำข้อ, retry ไม่เปลี่ยนโจทย์, คงรูปโจทย์, ไม่เปิด RPC ให้ authenticated, ปฏิเสธช่วงชั้นที่ไม่ระบุ และจัดการคลังหมดได้ ชุด raid ทั้งหมดผ่าน 17 tests
