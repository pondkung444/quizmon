# ป่าผลึก Endless — สรุปรันและอันดับ

หน้า `/2048` เปิดเป็นหน้าหลักพร้อมรันที่บันทึกไว้ ปุ่มเล่นต่อ และอันดับสามคนแรก มีหน้ารายการอันดับพร้อมโหลดหน้าถัดไปและอันดับของบัญชีปัจจุบัน ระยะเท่ากันได้อันดับร่วม นับเฉพาะห้องที่ผ่านสำเร็จ และเก็บรันที่ดีที่สุดหนึ่งรันต่อบัญชี

หน้าเล่นเก็บ HP/เกราะ ชาร์จ Auto เจตนาศัตรูและกระดาน เอาแถบห้อง/เหรียญ/ช่วยชีวิตด้านบนออก ย้ายเหรียญไปข้างคลังเรลิค สถานะเรลิคแสดงเฉพาะเมื่อมีผลที่ต้องติดตาม รูปใช้คลังป่าผลึกและเรลิคเดิมทั้งหมด

พักหรือออกเกมบันทึกในเครื่อง กลับเข้าหน้าหลักแล้วกดเล่นต่อได้ที่เบราว์เซอร์เดิม เปลี่ยนรันต้องยืนยันจบรันเดิม หน้าสรุปเปิดเมื่อแพ้หลังช่วยชีวิตหรือเลือกจบรัน แสดงห้องที่ผ่าน สถิติส่วนตัว อันดับ บอสที่ชนะ รูนสูงสุด จำนวนปัด และชุดคู่หู/เรลิค มีสถิติรวมและประวัติรันล่าสุดของบัญชี

## ข้อมูลและการตรวจผล

- `POST /api/2048/start` ตรวจเจ้าของคู่หู อ่านสเตตัสและคำถาม สร้าง seed จากเซิร์ฟเวอร์และ checkpoint รุ่น 1
- `POST /api/2048/competition` รับคำสั่งการเล่นครั้งละไม่เกิน 256 รายการ แล้วเล่นซ้ำด้วย engine production จาก checkpoint เดิม ตรวจประตู เรลิค ร้านค้า ควิซและสถานะรัน ไม่รับระยะทางหรือคะแนนที่ client อ้าง
- การเขียน checkpoint กับสถิติที่ดีที่สุดเป็น transaction เดียว ใช้ revision ป้องกันการส่งซ้ำและเขียนพร้อมกัน อัปเดตอันดับเมื่อผ่านห้องโดยไม่ต้องจบรัน
- คิวผลแยกตามบัญชี เก็บในเครื่องต่อได้ทั้งตอนออฟไลน์และเริ่มรันใหม่ ตัดคำสั่งออกเมื่อได้รับการตอบรับเท่านั้น รันที่ตรวจผลไม่ผ่านจะไม่ขวางคิวของรันใหม่
- `GET /api/2048/competition?page=0` อ่านอันดับหน้าละ 20 คนและสถิติของเจ้าของบัญชี อันดับส่งแค่ชื่อในเกม ระยะ ภาพ/สายคู่หูและอันดับ ไม่มีอีเมลหรือ checkpoint ของคนอื่น
- ตาราง `forest2048_runs`, `forest2048_scores` เปิด RLS อ่านได้เฉพาะเจ้าของ Client ไม่มีสิทธิ์เขียนหรือติดต่อ RPC ภายในเอง API เขียนด้วย service role เท่านั้น ดู SQL ใน `forest2048-competition-schema.sql` (applied ผ่าน Supabase MCP migration `forest2048_verified_competition`)
- ไม่มีการเพิ่ม EXP/แต้มเลี้ยง เหรียญ QuizMon หรือเปลี่ยนสเตตัสคู่หูจริง รันเก่าก่อนเปิดระบบอันดับเล่นต่อได้ แต่เริ่มรันใหม่จึงนับเข้าอันดับ
- การตรวจ replay ไม่ได้ห้ามบอทเล่นด้วยคำสั่งที่ถูกกติกา และชุดคำถามเดิมส่งเฉลยให้ client อยู่แล้ว จึงไม่ใช่ระบบสอบหรือแข่งขันแบบป้องกันการโกงเต็มรูปแบบ

Browser fixture ตรวจ 320×568, 390×844, 430×844: หน้าหลัก/อันดับ/เลือกคู่หู, ปัดสัมผัสจริง, บอทเล็กผ่านบอสไปห้อง 9, client และ server ตรงกัน, ออฟไลน์/ออกเข้าเล่นต่อ, response หายแล้ว retry ไม่ซ้ำ, ยืนยัน/ยกเลิกจบรัน, สรุปผลและสถิติ ไม่มี browser error ใช้ค่า fixture เพื่อเทส flow ไม่ใช่ผล balance ของนักเรียน

`tests/forest2048/competition-api-smoke.mjs` ทดสอบ API จริงด้วยบัญชี disposable และลบออกใน finally ไม่เขียน credentials ออกไฟล์ ไม่ส่งอีเมล ไม่สร้างคะแนนสาธารณะ (จบรันที่ 0 ห้อง)

ก่อน pilot: ใช้บัญชีนักเรียนสองคนเล่นผ่านห้องแรก ตรวจอันดับร่วมเมื่อระยะเท่ากัน พักแล้วออก/เข้าใหม่ เล่นจนแพ้และดูหน้าสรุป ตรวจสถิติหลังกลับหน้าหลัก ทดลองเน็ตหลุดแล้วกลับมาออนไลน์
