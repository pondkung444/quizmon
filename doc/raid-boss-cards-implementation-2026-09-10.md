# Raid Boss Cards — กติกาและผลพัฒนารุ่นแรก

วันที่ 10 กันยายน 2026 · branch `codex/raid-boss-cards`

พัฒนาตามคำสั่งให้เริ่มลงมือหลังยืนยัน [ทิศทางการออกแบบ](raid-boss-card-rework-direction-2026-09-10.md) แล้ว สถานะ “ยังไม่อนุมัติพัฒนา” ในเอกสารทิศทางเป็นประวัติ ณ เวลาบันทึก ไม่ใช่สถานะปัจจุบัน งานชุดนี้พร้อมทดลองในเครื่อง ยังไม่ได้ apply migration หรือเปิดกับผู้เล่นจริง

## สิ่งที่เล่นได้

- เข้าบอสโดยตรง คงสามด่านและการปลดล็อกตามลำดับ
- เลือดสองฝ่าย บอสประกาศท่าล่วงหน้า ผู้เล่นมีเวลาเลือกคำสั่ง
- การ์ดในมือสามใบ เก็บใบที่ไม่ใช้ เลือกจังหวะใช้พลัง และจั่วทดแทน
- ค่าสถานะกำหนดผลพิเศษ ไม่ถึงเกณฑ์ยังได้ผลพื้นฐาน ไม่ตอบข้อสอบทุกเทิร์น
- ภาพสนาม บอส มอน และเสียงจากไฟล์เดิมใน Git พร้อมเลือดลด/ฟื้นและภาพตอบสนอง
- รับอุปกรณ์เมื่อจบรอบ ดูสถิติและคำแนะนำ กลับไปปรับชุดเพื่อท้าอีกครั้ง
- ก่อนเข้าเห็น HP และโอกาสผลพิเศษเมื่อไม่ใส่ของเทียบชุดปัจจุบัน อัปเดตตามการจัดอุปกรณ์
- กลับบ้านเป็นการพักรอบ ไม่จบรอบและไม่แจกของ รีโหลดแล้วได้เลือด มือการ์ด และท่าบอสเดิม

## กติกาที่เลือกใช้ในต้นแบบ

| บอส | HP | พลังโจมตี | เกราะ | เกณฑ์เริ่มต้น |
| --- | ---: | ---: | ---: | ---: |
| จิ้งจอกหิมะเฒ่า | 240 | 22 | 8 | 48 |
| เสือหิมะจอมผา | 350 | 30 | 14 | 65 |
| พญาหมาป่าสายฟ้า | 460 | 38 | 18 | 80 |

พลังบอสคงที่ ไม่ปรับตามผู้เล่น ช่วงสองเริ่มเมื่อเหลือ HP 70% ช่วงสามที่ 35% เกณฑ์เพิ่มช่วงละ 4 และเพิ่ม 8 เมื่อต้องรับสายฟ้า

HP ผู้เล่น = 80 + round(HP stat × 1.5) ดาเมจโจมตีพื้นฐาน = round(10 + ATK × 0.45) ก่อนหักเกราะและคูณสถานะ DEF ลดดาเมจที่รับ สูงสุด 60% การประกาศท่าและดาเมจใช้สถานะก่อนลงการ์ด การโจมตีข้ามช่วงบอสจะไม่ทำให้บอสแอบตีแรงกว่าเลขที่ประกาศ

Stat ถึงเกณฑ์: ผ่านแน่นอน ต่ำกว่าเกณฑ์ไม่เกิน 25: โอกาส round(25 + ส่วนที่เข้าใกล้เกณฑ์ × 70)% ต่ำกว่านั้น: ใช้ผลพื้นฐาน เซิร์ฟเวอร์ทอยให้พร้อมการลงคำสั่ง ไม่มีปุ่มทอยอีกชั้น

| คำสั่ง | Stat | พลัง | ผลพื้นฐาน → ผลเมื่อผ่าน |
| --- | --- | ---: | --- |
| โจมตี | ATK | 0 | โจมตีพื้นฐานแน่นอน |
| ตั้งหลัก | DEF | 0 | ลดดาเมจ 45% และเพิ่มพลัง 1 แน่นอน |
| ตั้งรับสวนกลับ | DEF | 1 | ลดดาเมจ 35% → 70% และสวนเมื่อถูกโจมตีแล้วรอด |
| ก้าวพริบตา | SPD | 1 | ลด 15% → หลบทั้งหมดและเปิดจุดอ่อน; สายฟ้าลดได้ 70% |
| ทลายจังหวะ | ATK | 2 | โจมตี 80% → หยุดกระโจน/ชาร์จและเปิดจุดอ่อน |
| แทงจุดอ่อน | FOC | 1 | โจมตี 80% → 130% ทะลุเกราะ/หมอก |
| ลมหายใจฟื้นฟู | HP | 2 | ฟื้น 8 + HP × 0.2 → เพิ่มการฟื้น 50% |
| รวบรวมสมาธิ | FOC | 0 | เพิ่มพลัง 2 และแรงส่ง 25% → แรงส่ง 50% |
| พลังพิชิต | ATK | 3 | โจมตี 150% → 220% |

เริ่มพลัง 3 สูงสุด 5 จบเทิร์นเพิ่ม 1 ทุกครั้ง ใบที่ใช้ไปกองทิ้ง ไม่จั่วคืนทันที หมุนกองเมื่อไม่มีใบเหลือให้จั่ว โจมตีและตั้งหลักใช้ได้ตลอด การต่อสู้จบภายใน 20 เทิร์น ตั้งแต่เทิร์น 13 บอสเพิ่มตัวคูณโจมตีเทิร์นละ 8% ป้องกันตั้งรับ/ฮีลยื้อไม่สิ้นสุด

ท่าบอสสุ่มจากชุดตามชนิด/ช่วง ไม่ใช้ลำดับเดียวทุกครั้ง แต่ชาร์จตามด้วยสายฟ้า กระโจน/สายฟ้าหรือถูกขัดจังหวะตามด้วยเสียหลัก ผู้เล่นจึงเรียนรู้และวางแผนได้

## ความก้าวหน้าและรางวัล

ใช้ stat snapshot และอุปกรณ์ชุดเดิม บวกของแล้วจำกัดตาม cap เดิม FOC ไม่มีโบนัสจากของ Stage 4 ไม่ได้รับ stat/EXP จากการกดการ์ด คำแนะนำ FOC จึงชวนเปลี่ยนมอนหรือเปลี่ยนท่า

คะแนนชนะ = 80 + round(20 × สัดส่วน HP ที่เหลือ) คะแนนแพ้ = % เลือดบอสที่ลดได้ จำกัดไม่เกิน 79 มอบคะแนนนี้ให้ `claim_raid_reward` เดิมคำนวณคุณภาพตาม threshold ปัจจุบัน ไม่เปลี่ยนคุณภาพ/ค่าอุปกรณ์ที่ใช้ร่วมกับ PvP

คงไข่ `egg_epic_01` สำหรับชนะ ridge_storm: ครั้งแรกแน่นอน หลังจากนั้นฐาน 10% และกติกา pity เดิม (ตรวจ meter ≥ 10 ก่อนสุ่ม/เพิ่ม meter รอบที่พลาด) การชนะเก่ารวมอยู่ในการนับครั้งแรกด้วย

ค่าตัวเลขเป็นจุดเริ่มทดลอง ไม่ใช่ข้อสรุปว่าบาลานซ์กับผู้เล่นจริงแล้ว ควรวัดอัตราเล่นซ้ำ อัตราชนะตามช่วง stat ความยาวรอบ คุณภาพของ/ไข่ต่อผู้เล่น และท่าที่ถูกใช้ก่อนขยายการเปิดใช้งาน

## การเก็บสถานะและการเข้าถึง

- `raid_card_battles` เก็บ ruleset 2, revision, สถานะทั้งรอบ และสถิติจบรอบ
- สร้างรอบผ่าน RPC ใหม่ซึ่งใช้การตรวจมอน กุญแจ ปลดล็อก และ snapshot ของ RPC เดิม แล้วตัด steps ที่ไม่ได้ใช้
- `card_battle`/`card_reward` แยกจาก phase เดิม RPC ตอบคำถามหรือรับรางวัลเก่าไม่ข้ามขั้นให้รอบใหม่
- การเริ่มซ้ำของผู้เล่นล็อกด้วย advisory lock คืนรอบเดิมโดยไม่ใช้กุญแจเพิ่ม
- เซิร์ฟเวอร์ยืนยันเจ้าของและคำนวณคำสั่งทั้งหมด บราวเซอร์ส่งเฉพาะ run/revision/card
- เขียนผลผ่าน service role เท่านั้น ล็อกแถวและเทียบ revision การส่งซ้ำหรือแท็บเก่าคืนสถานะล่าสุด
- ผู้เล่นอ่านได้เฉพาะรอบตนเอง ไม่มีสิทธิ์แก้สถานะหรือเรียก RPC บันทึกผลโดยตรง
- รับรางวัลโดยเปลี่ยน phase และเรียก RPC เดิมใน transaction เดียว การลองซ้ำได้ของชิ้นเดิม
- รอบ legacy ค้างอยู่เล่นตามระบบเดิมจนจบ ปิด feature flag แล้วรอบ v2 ที่เริ่มไว้ยังเล่นต่อได้

## การตรวจสอบ

`npm run test:raid` ผ่าน 13 tests: กฎการ์ด/พลัง/มือ/สถานะ, ท่าประกาศตรงผล, serialize/resume, การต่อสู้สุ่มหลายรอบ และ PostgreSQL integration

PostgreSQL integration ใช้ PGlite รัน migration ใหม่กับฟังก์ชัน `start_raid_run` และ `claim_raid_reward` จริงจาก migration เดิม ภายใต้ schema fixture ทดสอบเจ้าของ/สิทธิ์, การปลดล็อก, หักกุญแจครั้งเดียว, CAS ส่งซ้ำ, จบรอบ, รับรางวัลซ้ำ, legacy isolation, ไข่ครั้งแรกและ pity ใช้ข้อมูลทดสอบทั้งหมด ไม่เชื่อม production

การจำลอง 100 seeds ต่อชุดค่าสถานะ 35/60/85 ที่ใช้ policy ตัดสินใจเดียวกัน:

| ด่าน | 35 | 60 | 85 |
| --- | ---: | ---: | ---: |
| mist | 9 | 100 | 100 |
| gale | 0 | 91 | 100 |
| storm | 0 | 0 | 100 |

นี่เป็นการตรวจแนวโน้มความก้าวหน้า ไม่ใช่อัตราชนะจริงหรือสัญญาว่าทุก build ชนะเท่ากัน

Browser ทดสอบ 390×844 และ 1365×900: ภาพจาก Git โหลดครบ, ไม่มีหน้าล้นแนวนอน, เลือก/ใช้คำสั่ง, รีโหลดสถานะเดิม, ชนะ mist, แพ้ storm, สลับครบสามบอส, reduced motion และไม่มี page error ใช้ Arena/engine เดียวกับจริง แต่การเก็บสถานะหน้า preview ใช้ localStorage ส่วนการเก็บฐานข้อมูลตรวจแยกด้วย integration test

Production build, TypeScript และ lint ไฟล์ที่แก้ผ่านแล้ว การเรียก Next.js Server Actions ครบวงจรกับ Supabase จริงยังต้องตรวจใน staging ที่ apply migration แล้ว

## เปิดทดลองและนำขึ้นระบบ

ใน PowerShell:

```powershell
npm ci
$env:RAID_CARD_PREVIEW='true'
npm run dev -- --hostname 127.0.0.1 --port 3108
```

เปิด `/raid/preview` เลือกสามบอสและสี่ชุดเพื่อทดลอง หน้า preview เปิดได้เฉพาะ development และต้องเปิด flag ไม่มีรางวัลจริง

เมื่อจะปล่อยใช้งาน:

1. Apply `supabase/migrations/20260910044249_raid_card_battles_v2.sql` ใน staging ก่อน
2. ใช้ Supabase env/service key ตามรูปแบบเดิมของแอป แล้วตั้ง `RAID_CARD_BATTLES_ENABLED=true`
3. ตรวจเริ่ม → เล่น → ปิด/เปิด → จบ → รับของ → จัดชุด/เริ่มใหม่ รวมสองแท็บและจำลองเน็ตหลุด
4. หลังตรวจผ่านจึงนำ migration/แอปขึ้น production และเปิด flag

Rollback: ตั้ง `RAID_CARD_BATTLES_ENABLED=false` เพื่อให้รอบใหม่กลับใช้ legacy คงโค้ด v2 และตารางไว้จนรอบ v2 ที่ค้างจบ ไม่ลบตารางหรือย้อนแอปเป็นเวอร์ชันที่อ่าน card phases ไม่ได้

ไฟล์หลัก: `src/lib/raid/cards/engine.ts`, `server.ts`, `src/app/raid/card-actions.ts`, `src/components/raid/CardBattleArena.tsx`, `RaidCardBattle.tsx`, `RaidCardReadiness.tsx` และ migration ข้างต้น
