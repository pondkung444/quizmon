# Responsive battle layout

Desktop and landscape tablets now use the approved two-column design: board on the left, companion/enemy portraits, HP, upcoming action and input guide on the right. Coins and relics occupy the free space in the shared top header between the title and sound/pause buttons, freeing the bottom row for gameplay. Long inventories scroll horizontally within that space. Portrait phones retain their existing layout.

The same DOM and game state are retained across viewport changes. CSS selects the full layout at landscape widths of at least 960px and heights of at least 600px, or on fine-pointer desktops at least 1100px wide. Landscape viewports at least 640px wide and 320–599px tall use a compact two-column layout. Smaller unsupported landscape viewports retain the existing rotate notice.

Regional and relic status details remain available through the info button without creating implicit grid tracks. `wide.css` is loaded after portrait and regional styles. Its repeated root ID specificity overrides the existing `main:has(status)` placement rules; it is not a requirement for duplicate DOM IDs.

Validation uses fixture accounts in a local browser, not production accounts. Run `node tests/forest2048/intent-responsive.cjs` with Playwright available. The test requires Node's native TypeScript support for the replay fixture.

Coverage: 18 viewports from 320x480 portrait and 640x320 landscape through 1920x1080 desktop; all three bosses and active relic status; no board/header/announcement/inventory overlap or horizontal overflow; info dialog return; touch swipes on phones and tablets; desktop arrow input; phone and tablet rotation preserving game state; pause preventing keyboard moves. Screenshots are written to `output/intent-responsive`.
