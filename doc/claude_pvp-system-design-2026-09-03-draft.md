# PvP System — Design Draft (หลังรอบกริล)

> **สร้าง:** 3 กันยายน 2026 · **สถานะ: ร่างต้น — เคาะโครงสร้างหลักแล้ว ยังไม่ได้ implement**

## 0. Concept ต้นฉบับ (จากปอนด์)

เล่นเฉพาะเพื่อนกัน — คนนึงกดท้า คนนึงกดรับ → เข้าหน้าเลือก Qmon + ใส่อุปกรณ์ที่จะเข้าสู้
สไตล์การ์ดเกม: จั่วการ์ดบอก **บท/วิชา/ความยาก** 5 ใบ → เลือก 1 ใบให้อีกฝั่งทำ
ทำได้ = ไม่โดนดาเมจ · ทำไม่ได้ = โดนดาเมจ · อีกฝั่งก็เลือกการ์ดมาให้เราทำสวนกลับ

## 1. มติที่ล็อกแล้ว

| หัวข้อ | มติ | เหตุผล/หมายเหตุ |
|---|---|---|
| **โหมดเวลา** | Async — ไม่ต้องนัดเวลาเข้าเล่นพร้อมกัน | Sync/realtime เพิ่งถูกตัดออกจาก Boss Raid ถาวรเพราะปัญหาเดียวกัน |
| **โครงสร้างยก** | สลับกันทีละคน (ping-pong) ไม่ใช่ blind-submit พร้อมกัน | เข้ากับ async ดีกว่า ไม่มี deadlock รอทั้งคู่ครบ |
| **ใครเล่นก่อน** | ตัดสินด้วย **SPD** | SPD สูง = ได้ส่งการ์ดก่อนในยกแรก |
| **ความยาวแมตช์** | ไม่จำกัดยก จนกว่าเลือดหมด แต่มี **เพดาน 30 ยก** | ถึงเพดานแล้วตัดสินด้วยเลือดคงเหลือ (มากกว่าชนะ) |
| **Timeout ต่อยก** | ไม่ตอบภายใน **3 วัน** → แมตช์ถูกทิ้ง | ไม่มีผู้ชนะ ไม่กระทบสถิติทั้งสองฝ่าย |
| **แพ้เสียอะไรไหม** | ไม่ติดลบ — แต่ได้ EXP **น้อยกว่า**ผู้ชนะ | ตาม principle "no punishment" ของเกม ผู้ชนะได้มากกว่า ไม่ใช่ผู้แพ้ถูกหัก |
| **ที่มาการ์ด** | สุ่ม **เอียงตามสาย (lane) ของ Qmon ที่เลือกใช้** | Qmon สาย math → การ์ดเลขเยอะ · สาย balance → กระจายเท่าๆ กัน (ผูก Qmon choice กับกลยุทธ์การ์ด) |
| **เอฟเฟกต์การ์ด** | มีตั้งแต่ v1 — เป็นจุดขายของระบบ ไม่ใช่ v1.1 | ปอนด์ยืนยันชัดเจน |
| **จำนวนเอฟเฟกต์** | 4-6 แบบ ในรุ่นแรก | กลางๆ ครอบคลุมเกมเพลย์หลัก ไม่เฟ้อ |
| **เอฟเฟกต์ผูกกับความยากไหม** | **ไม่ผูก** — สุ่มอิสระ | การ์ดง่ายก็อาจมีเอฟเฟกต์แรงได้ → คาดเดายากขึ้น สนุกกว่า |
| **อุปกรณ์ที่ใช้สู้** | แยกชุด PvP โดยเฉพาะ ไม่ใช้ร่วมกับ Boss Raid | เลือกเองก่อนเข้าดวลต่างหาก |
| **คู่ต่อสู้** | เพื่อนเท่านั้น (ตามไอเดียต้นฉบับ) | ตรงกับระบบเพื่อนที่มีอยู่แล้ว |
| **Junior/Senior** | **แยกขาดเด็ดขาด** — junior ท้าได้แค่ junior, senior ท้าได้แค่ senior | กันการ์ดบทที่อีกฝ่ายไม่มีในหลักสูตร |
| **คำขอท้าค้าง** | จำกัด **3-5 คำขอพร้อมกัน** ต่อคน | กันสแปม |
| **EXP → leaderboard** | `source='pvp'` ตั้งแต่วันแรก — **ให้ EXP แต่ไม่นับ leaderboard หลัก** | แบบเดียวกับ `topic_select` กัน backfill ทีหลัง |
| **EXP → เพดาน 180/วัน** | **แยกออก — PvP EXP ไม่ตันที่ 180** ตันที่ตั๋วแทน | ดูเหตุผลเต็มใน §5 |
| **ตัวจับเวลาต่อยก** | **มี — 60 วินาที** หมดเวลา = ตอบผิด | ตื่นเต้นกว่า กันเปิดหนังสือ เชื่อมกับ SPD ที่ให้วินาทีเพิ่มได้ |
| **ปฏิเสธคำท้า** | **แจ้ง**อีกฝ่ายว่าถูกปฏิเสธ | ไม่ปิดบัง |
| **เกณฑ์บทที่เข้า pool การ์ด** | **สุ่มจากทุกบทที่มีข้อสอบเลย** ไม่ใช้เกณฑ์ ≥50 ข้อแบบ topic-select | ตั้งใจต่างจาก topic-select |
| **เห็น loadout อีกฝ่ายก่อนดวลไหม** | **ไม่เห็น — blind** ทั้งคู่เลือกเอง เปิดเผยพร้อมกันตอนเริ่มดวลจริง | กันวางแผนเอาเปรียบ |
| **สถิติ/อันดับหน้าสังคม** | **มี** — เพิ่ม "จำนวนชนะ/เสมอ PvP" ในหน้าโปรไฟล์เท่านั้น **ไม่มี leaderboard แยก** | ขอบเขตเล็ก ไม่เพิ่มระบบใหม่ |
| **สกิล/แกล้งนอกเหนือเอฟเฟกต์การ์ด** | **ไม่มีใน v1** เก็บไว้ v2 เหมือนเดิม | v1 มีแค่เอฟเฟกต์ติดการ์ดก็พอ |
| **จังหวะเลือก Qmon+อุปกรณ์** | ผู้ท้าเลือกตอนส่งคำท้า → ผู้รับเลือกตอนกดรับ → เข้าดวลได้ทันที | เร็วกว่ารอ lobby |
| **บทข้อสอบน้อยมาก (<10 ข้อ)** | อนุญาตทุกบทที่มีข้อสอบ **≥1 ข้อ** แต่ระบบกันจั่วข้อซ้ำภายในแมตช์เดียวกัน | ไม่ตัดบทออก แค่กันซ้ำ |
| **ระบบเลือด vs หลัก "ไม่มี HP" ของ raid** | **ไม่ขัดกัน** — ปอนด์ยืนยันชัดเจนว่า PvP เป็นคนละเกมกับ raid มีเลือดได้ | raid ตัดสินไม่เอา HP ด้วยเหตุผลเฉพาะบริบทตัวเอง ไม่ใช่กฎครอบทั้งเกม |
| **ชื่อฟีเจอร์ที่ผู้เล่นเห็น** | **"ประลอง"** (ไม่ใช้คำว่า PvP หรือ ท้าทาย เพราะ "ท้าทาย" ถูก raid ใช้แล้ว) | ตามหลัก precedent เดียวกับที่เลือก "ท้าทาย" แทน "พิชิต" — โทนเป็นมิตร ไม่กดดัน เข้ากับที่เล่นได้แค่เพื่อน |
| **ตำแหน่งเมนูล่าง** | แทนที่ **"หอเกียรติยศ"** ในเมนูล่าง 4 ปุ่ม (บ้าน / สังคม / ฟาร์ม / **ประลอง**) | หอเกียรติยศมีคนเข้าน้อย (ดูประวัติแชมป์เก่า) ไม่คุ้มพื้นที่เมนูล่าง — ย้ายเข้าไปเป็นลิงก์ในแท็บ "อันดับ" ของหน้าสังคมแทน เพื่อไม่ขัดกฎ "เมนูย่อยสังคมมี 3 แท็บเท่านั้น" ที่ล็อกไว้แล้ว |
| **หน้าจอตอนแพ้** | เน้นความพยายาม เช่น "สู้ดีมาก! {ชื่อ} สู้จนนาทีสุดท้าย" **ไม่พูดคำว่า "แพ้" เลย** | ตรงกฎเหล็ก "feedback เชิงบวกทั้งหมด" ที่ครอบทั้งเกม (ไม่ใช่แค่ raid) |
| **Qmon stage ที่เข้า PvP ได้** | **stage 4 เท่านั้น** เหมือน raid | สเตตัสเป็น snapshot นิ่งแล้วตอน stage 4 เทียบกันยุติธรรม — เลือกจากฟาร์ม/สมุดสะสมได้ (เหมือน raid) |
| **หน้าจอตอนชนะ** | เน้นความสนุกของการดวล เช่น "ดวลมันส์มาก! ชนะไปแล้ว" **ไม่เน้นเหนืออีกฝ่าย** | กัน gloat ใส่เพื่อนที่แพ้โดยไม่ตั้งใจ — ต่างจากโหมดอื่นตรงที่มีเพื่อนเห็นผลด้วย |

## 2. ยังไม่ตัดสิน / เปิดอยู่

ทุกอย่างที่เคยเปิดไว้ (stat mapping, เอฟเฟกต์การ์ด, เพดานตั๋ว) ปิดครบแล้ว — ไม่มีหัวข้อเปิดค้างในระดับ design decision อีก เหลือแค่**ตัวเลขจริงที่ต้องรอข้อมูล** (ดาเมจฐาน, % ลดดาเมจ DEF, % คริจาก FOC) ซึ่งเป็นเรื่อง tuning ไม่ใช่การตัดสินใจเชิงกลไก

## 3. Stat mapping — เวอร์ชันสุดท้าย

> เปลี่ยนจากร่างแรก: FOC เดิมเสนอเป็น "แต้มตัดตัวเลือกที่ใช้แล้วหมด" — ปอนด์ไม่ชอบ เปลี่ยนเป็น **"โอกาสคริ"** แทน ทำให้ ATK+FOC จับคู่เป็น "แกนรุก" สมมาตรกับ HP+DEF ที่เป็น "แกนรับ"

| Stat | บทบาทใน PvP |
|---|---|
| **HP** | เลือดตั้งต้น |
| **ATK** | ดาเมจฐานเมื่ออีกฝั่งตอบการ์ดที่เราส่งผิด |
| **DEF** | ลดดาเมจที่รับ (%) ตอนเราตอบผิด |
| **SPD** | ใครส่งการ์ดก่อนยกแรก (ล็อกแล้ว) + วินาทีตอบเพิ่มจากฐาน 60 วิ |
| **FOC** | **โอกาสคริ** — % ที่จะได้ดาเมจโบนัสเมื่ออีกฝั่งตอบการ์ดที่เราส่งผิด (สุ่มทุกครั้งที่ตี ไม่ใช่แต้มสะสมที่ใช้แล้วหมด) |

⚠️ ตัวเลขจริง (ดาเมจฐานต่อความยาก, % ลดดาเมจ DEF, % คริจาก FOC) ยังไม่จูน — รอข้อมูลจริงเหมือนที่เคยทำตอนจูน FOC/SPD ของ raid ห้ามเดาเลขไปก่อน implement

## 3.1 เอฟเฟกต์การ์ด — เซ็ตสุดท้าย 6 แบบ

การ์ดส่วนใหญ่ (แนะนำ ~40%) ควรเป็นการ์ด "เปล่า" ไม่มีเอฟเฟกต์ กันการ์ดทุกใบจัดจ้านจนสับสน

| ชื่อ (ร่าง) | กลไก | เอียงเข้าข้างใคร |
|---|---|---|
| **สวนกลับ** | ตอบถูก → ดาเมจสะท้อนกลับใส่คนส่งเท่าดาเมจฐานของการ์ดนั้น | เสี่ยงฝั่งคนส่ง |
| **เจาะเกราะ** | ตอบถูกก็ยังโดนดาเมจเล็กน้อย (ไม่สน DEF) | เอียงเข้าข้างคนส่ง |
| **ฮีลเมื่อสำเร็จ** | ตอบถูก → ได้เลือดคืนแทนที่จะแค่ไม่โดน | เอียงเข้าข้างฝั่งตอบ |
| **เดิมพันสูง** | ตอบผิด = ดาเมจ 2 เท่าปกติ | เอียงเข้าข้างคนส่ง |
| **เร่งเวลา** | เวลาตอบเหลือ 30 วิ แทน 60 | เอียงเข้าข้างคนส่ง |
| **ดูดเลือด** | ตอบผิด → นอกจากโดนดาเมจปกติ **คนส่งได้เลือดคืนเท่าดาเมจที่สร้างได้** | เอียงเข้าข้างคนส่ง |

**วิวัฒนาการของเซ็ตนี้ (สำหรับอ้างอิง):** เริ่มจาก 5 ใบที่เอียงเข้าข้างคนส่งเกือบทั้งหมด → เพิ่ม "ใบ้ตัวเลือก" ให้ฝั่งตอบมีของบ้าง (คู่กับ FOC แบบเดิม) → พอ FOC เปลี่ยนเป็นคริ กลไก "ตัดตัวเลือก" ก็ไม่เชื่อมกับสเตตัสไหนแล้ว → ปอนด์อยากได้เอฟเฟกต์เข้าข้างคนส่งเพิ่มอีก → แทนที่ "ใบ้ตัวเลือก" ด้วย **"ดูดเลือด"** ซึ่งเป็นกระจกสะท้อนของ "ฮีลเมื่อสำเร็จ" (ฮีลคนตอบตอนสำเร็จ ↔ ฮีลคนส่งตอนคนตอบพลาด) — จบที่สัดส่วน **4 ใบเอียงคนส่ง (เจาะเกราะ/เดิมพันสูง/เร่งเวลา/ดูดเลือด) : 1 ใบเอียงฝั่งตอบ (ฮีลเมื่อสำเร็จ) : 1 ใบกลางๆ/เสี่ยงกับคนส่งเอง (สวนกลับ)**

## 5. EXP & ตั๋วเข้าเล่น (เพิ่มหลังรอบกริลที่ 3)

**แนวคิดต้นฉบับจากปอนด์:** ไม่จำกัด EXP ต่อวันสำหรับ PvP แต่จำกัดด้วย "ตั๋วเข้าเล่น" แทน — แจกฟรีวันละ 2 ใบ + ได้อีก 1 ใบเมื่อลงท้าทาย (raid) จบ 1 รอบ เป้าหมาย: ดันคนเข้าเล่นท้าทายเพิ่ม + ดันคนใช้ระบบเพื่อน

### จุดชนที่เจอ + วิธีแก้

ระบบมี **soft cap 180 EXP/วัน (Bangkok day)** ฝังใน `src/lib/exp.ts` (protected file) ครอบทุกโหมดที่ผ่าน `calculateExpForAnswer()` — ถ้า PvP ต้องไม่มีเพดานจริง ต้องขอ exception เฉพาะจุด

**ตัดสินใจแล้ว:** ✅ **แยก PvP EXP ออกจากเพดาน 180 จริง** (ไม่ใช่แค่นับรวมแล้วตันไปเอง)

**เหตุผลที่เปลี่ยนใจจากข้อเสนอแรกของ Claude (ตอนแรกแนะนำให้นับรวมในเพดานเดียวกัน):**
- ความเสี่ยง "ไม่มีใครเล่น PvP เลย" (ซ้ำรอยระบบท้าทายตอนเปิดใหม่ๆ ที่ engagement ต่ำ) ร้ายแรงกว่าความเสี่ยง over-farm
- มีแรงเสียดทานธรรมชาติกันการฟาร์มอยู่แล้ว: ตั๋วจำกัด (2-3 ใบ/วันโดยประมาณ) + ต้องมีเพื่อนจริงมาตอบคำถามด้วยจริงทั้งคู่ — ฟาร์มได้ก็ต่อเมื่อดึงเพื่อนมาเล่นจริง ตรงเป้าหมาย social เป๊ะ
- EXP ที่ได้ยังมาจากการตอบคำถามจริงทุกข้อ ไม่ผิดหลัก "การเรียนคือแกน"

**วิธี implement ที่ปลอดภัย:** เติมเงื่อนไข "ถ้า `source='pvp'` ข้าม soft-cap check" จุดเดียวใน `calculateExpForAnswer()` — ไม่แตะตรรกะอื่นในไฟล์ (แบบเดียวกับ exception ที่เคยให้ `computeRawStats()` ใน `evolution.ts`)

### มติเรื่องตั๋ว

| หัวข้อ | มติ |
|---|---|
| แจกฟรี | **2 ใบ/วัน** |
| ได้เพิ่ม | **+1 ใบ** เมื่อลงท้าทาย (raid) จบ 1 รอบ |
| หักตั๋วตอนไหน | **หักจากผู้ท้าเท่านั้น** ตอนกดส่งคำท้า — ผู้รับเล่นฟรี ไม่เสียตั๋ว |
| ปฏิเสธ/timeout ก่อนเริ่มเล่น | **คืนตั๋ว**ให้ผู้ท้าอัตโนมัติ |
| คำท้าค้างหมดอายุกี่นาน | **24 ชม.** (สั้นกว่า timeout ระหว่างเล่นที่ 3 วัน เพราะแค่กดรับควรเร็วกว่าการเล่นจริง) |
| เพดานสะสมตั๋ว | **15 ใบ** — กันตั๋วล้นคลัง (เทียบ raid ticket cap 10 ใบ) |

## 7. ทางเข้า, หน้าสถานะ, และการแจ้งเตือน (เพิ่มหลังรอบกริลที่ 4)

### ทางเข้า

| หัวข้อ | มติ |
|---|---|
| ตำแหน่งเมนูล่าง | แทนที่ "หอเกียรติยศ" — เมนูล่างใหม่: **บ้าน / สังคม / ฟาร์ม / ประลอง** (ยังคง 4 ปุ่มตามกฎเดิม) |
| หอเกียรติยศไปไหน | ย้ายเข้าไปเป็นลิงก์ใน**แท็บ "อันดับ"** ของหน้าสังคม — ไม่เปิดแท็บที่ 4 เพราะกฎ "เมนูย่อยสังคมมี 3 แท็บเท่านั้น" ล็อกไว้แล้ว |
| ชื่อฟีเจอร์ | **"ประลอง"** (ไม่ใช้ PvP/ท้าทาย — ท้าทายถูก raid ใช้แล้ว) |

### หน้าหลัก "ประลอง" — จัดกลุ่มสถานะ

แยก 2 ส่วน:
1. **"ถึงตาคุณ"** — ขึ้นก่อน เห็นชัดสุด (แมตช์ที่รอเราตอบการ์ด)
2. **ส่วนอื่นซ้อนด้านล่าง** — คำท้าค้าง (รอกดรับ/ถูกท้า), รอคู่ต่อสู้ตอบ, จบแล้ว

### Push Notification

| จุด | ส่ง push ไหม |
|---|---|
| คำท้าใหม่เข้ามา | ✅ ส่ง |
| ถึงตาคุณ (คู่ต่อสู้ส่งการ์ดมาแล้ว) | ✅ ส่ง |
| ผลการประลองออกแล้ว (จบแมตช์) | ❌ ไม่ส่ง — เช็คในแอปเอง |

### Badge ปุ่มเมนูล่าง

- มีตัวเลขแดงบอกจำนวนเรื่องค้าง เห็นได้จากนอกแอป
- **นับรวม:** "ถึงตาคุณ" + คำท้าใหม่ที่ยังไม่กดรับ/ปฏิเสธ → รวมเป็นเลขเดียว
