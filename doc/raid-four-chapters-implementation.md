## กติกาที่ล็อกในรุ่นนี้

เลือดมอน = 80 + round(HP stat × 1.5)
เลือดบอส: 200 / 270 / 430; จำนวนข้อ: 5 / 6 / 8
ดาเมจฐาน = HP บอส / จำนวนข้อ × (1.05 + min(0.45, ATK / 250))

- โจมตีหนัก: ฐาน × 1.20
- ดูดเลือด: ฐาน × 0.90; ฟื้นจากดาเมจที่ทำได้จริง × (0.40 + min(0.20, HP / 500))
- ตั้งรับสวนกลับ: ฐาน × 0.80; รับดาเมจเพียง 45%; ถ้ายังยืนอยู่และบอสโจมตี สวนฐาน × (0.40 + min(0.20, DEF / 500))
- เจาะเกราะ: ฐาน × (1 + min(0.15, FOC / 800)); ข้ามเกราะ
- ขัดจังหวะ: ฐาน × (0.85 + min(0.15, SPD / 800)); หยุด charge/thunder แล้วบอสเสียหลักข้อหน้า
- เปิดจุดอ่อน: ฐาน × 0.60; เพิ่มการโจมตีครั้งถัดไป 60% + min(30%, FOC / 400) ใช้แล้วหมด ไม่สะสมทบ
- ตอบผิด: ฐาน × 0.25 เท่ากันทุกใบ ไม่ฮีล ไม่สวน ไม่ขัดจังหวะ ไม่สร้างจุดอ่อนใหม่; โบนัสจากจุดอ่อนที่เปิดไว้ก่อนหน้ายังใช้กับการโจมตีนี้และหมดไป
- ไม่มีคริติคอลสุ่มใน ruleset 4; FOC และ SPD เพิ่มพลังสกิลโดยตรง รุ่นเดิมยังมีคริติคอลตามกติกาเดิม
- บอสตั้งเกราะลดดาเมจ 40% เว้นเจาะเกราะเมื่อตอบถูก
- ดาเมจบอส = round(ATK บอส × 1.35 × ตัวคูณท่า × (1 − min(0.50, DEF / 250)))
- ตัวคูณท่า: claw 1; brace 0.55; charge 0; thunder 2.1; recover 0
- ลำดับ: โจมตี → ดูดเลือด → บอสสวนถ้ายังอยู่และไม่ถูกขัด → สวนกลับถ้ามอนยังยืน → ตรวจจบรอบ
- ฆ่าบอสด้วยการโจมตีแรกแล้วบอสไม่สวน เลือดไม่มีค่าติดลบ ฮีลไม่เกินเลือดสูงสุด
- ชนะเมื่อ HP บอสหมด; แพ้เมื่อ HP มอนหมดหรือครบข้อ ไม่ใช้ประตู stat/accuracy ตอนจบ
- เปิดจุดอ่อนไม่ถูกสุ่มในข้อสุดท้าย และไม่สุ่ม charge เป็นท่าของข้อสุดท้าย

เหตุผลการจูน: เดิมทดลองเปิดจุดอ่อนโจมตี 90% แล้วการกดซ้ำคุ้มเกินไป จึงลดเป็น 60% ให้ใช้เตรียมคอมโบ

## มือการ์ดและข้อมูล

- นิยามบท: คู่ (coalesce(branch,subject), ชื่อ chapter ที่ตัดช่องว่าง); ถ้า chapter ว่างใช้ category
- สุ่ม distinct บทก่อนสุ่มข้อ เพื่อไม่ให้บทที่มีจำนวนข้อเยอะได้เปรียบ
- ไม่สุ่มข้อที่ตอบแล้วในรอบเดียวกัน
- ทุกมือมีโจมตีหนัก และถ้ามีอย่างน้อยสองบทมีดูดเลือด
- ที่เหลือสุ่มจากสวนกลับ/เปิดจุดอ่อน และสกิลตามท่าบอส (เจาะเกราะเมื่อ brace, ขัดจังหวะเมื่อ charge/thunder)
- ข้อสุดท้ายไม่มีเปิดจุดอ่อน; หากตัวเลือกสกิลไม่ครบใช้เจาะเกราะเป็นตัวเลือกโจมตีทั่วไป
- บทน้อยกว่า 4 แสดงเท่าที่มี; ไม่มีข้อเหลือให้จบรอบด้วยคะแนนผลงานปัจจุบัน
- ก่อนเริ่มตรวจว่ามีโจทย์พร้อมใช้อย่างน้อยตามจำนวนข้อด่าน จึงไม่หักกุญแจเมื่อคลังไม่พอ
- ตาราง raid_chapter_offers เก็บ snapshot คำถามและเฉลยให้ service_role เท่านั้น ไม่มีสิทธิ์อ่าน/เขียนจาก anon/authenticated
- RPC สุ่มคืนเฉพาะ id, chapter, subject, difficulty, cardId ไม่ส่งโจทย์หรือเฉลย
- เมื่อเลือก snapshot ถูกย้ายเข้า raid_card_questions การแก้โจทย์ต้นทางไม่เปลี่ยนโจทย์ที่เสนอไปแล้ว
- ล็อกตาม run และ revision พร้อม unique selection เพื่อรับมือ retry/หลายแท็บ
- บันทึกมือที่เสนอและ selected_at สำหรับวิเคราะห์การเลือก คำตอบอยู่ใน raid_card_questions/quiz_attempts ผลสกิลอยู่ใน battle.log ผลรอบ/รางวัลใช้ระบบเดิม

## สิ่งที่ทดสอบแล้ว

- 26 tests: กติกาเก่าและใหม่, ขอบเขต HP, ผลแต่ละสกิล, resume JSON
- PostgreSQL/PGlite ใช้ migration และ RPC จริง: ownership, สิทธิ์ตาราง/RPC, กุญแจ, 4 บทไม่ซ้ำ, retry มือเดิม, เลือกได้ใบเดียว, เฉลยไม่ออกในผลมือ, question snapshot, ข้อมูลไม่พอ, จบรอบเมื่อหมดโจทย์, รางวัลรับซ้ำไม่เพิ่ม
- Browser: 390×844, 1024×768, 1440×900; ทั้งสามบอสอย่างละชนะและแพ้; refresh ระหว่างโจทย์; ปุ่มเฉลย/ไปต่ออยู่ในจอ; ไม่พบ page errors
- TypeScript และ ESLint ของไฟล์ที่แก้ผ่าน
- Next.js production build ผ่านด้วยค่าตั้ง Supabase จำลอง ไม่ได้ใช้เป็นหลักฐานเชื่อมฐานข้อมูลจริง
- จำลอง 300 seed × 3 บอส × 3 ชุด stat × 3 อัตราตอบถูก × 2 วิธีเลือก = 16,200 รอบ
- ที่ตอบถูก 80% ชุดเริ่มต้น stat 40: กดตีหนักชนะ 69/68/8%; เลือกสกิลตามมูลค่าคาดหมายชนะ 74/74/78% ตามสามด่าน
- การจำลองสมมติอัตราตอบถูกเท่ากันทุกบทและใช้มือที่จำลองตามกติกา SQL ไม่ใช่ผลทดลองกับเด็กจริง แผน tactical ไม่ได้เหนือกว่าทุกชุด stat จึงยังต้องเก็บข้อมูลจริงหลังปล่อย

## ลำดับเปิดใช้

1. Deploy โค้ดที่รองรับ ruleset 4 โดย RAID_CHAPTER_CARDS_ENABLED=false ก่อน โค้ดยังอ่านฐานเดิมได้
2. Apply migration 20260927162425_raid_four_chapter_hands.sql บน staging และทดสอบด้วยบัญชีจริงก่อน production
3. ตรวจทั้งรอบเก่าค้าง รอบใหม่ เลือกบท ตอบ ใช้สกิล จบรอบ และรางวัล รวมรีเฟรช/ส่งซ้ำ/เครือข่ายหลุด
4. Apply migration บน production หลังตรวจผ่าน แล้วเปิด RAID_CHAPTER_CARDS_ENABLED=true สำหรับรอบใหม่เมื่อถึงขั้นตอนปล่อย
5. ตรวจ error rate, การเริ่ม/จบรอบ, การเลือกสกิล, ความถูกต้อง และรางวัล

ปิดรับรอบใหม่รุ่น 4: ตั้ง RAID_CHAPTER_CARDS_ENABLED=false แล้ว deploy การตั้งค่า โดยคงโค้ดที่อ่าน ruleset 4 อยู่ รอบที่เริ่มแล้วจะเล่นต่อด้วย requested_ruleset/state เดิม

อย่าย้อนโค้ดกลับไปก่อนรองรับ ruleset 4 ขณะที่มีรอบรุ่น 4 ค้าง และอย่าลบตารางมือหรือแก้ state ของรอบค้างเพื่อย้อนกลับ
